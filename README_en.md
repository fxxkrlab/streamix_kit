# StreamixKit

SXAPI v1 integration documents and an asynchronous Rust SDK for player authors.

**0.1.0-rc.2 · Build 20261114.013 — specification-sync candidate, not released.**

The contracts are bound to server source `fc979d3b95bb1ebbd408a55243be3cc35c34a7a6` (0.9.0-rc.17 candidate, not yet published), with minimum server candidate **0.9.0-rc.9**; see [SOURCE.json](spec/SOURCE.json). The RC17 specifications are additive over RC16: the player subset stays at 116 operations. `Media` adds the required fields `best_version` (a nullable `BestVersion`: the `id`, `resolution`, `width`, `height`, `hdr_type`, `bitrate_bps` and `dolby_vision_profile` of the work's best version, the same as the first entry of `GET /media/{id}/versions`; only measured facts, null until measured; the whole field is null when the work has no current main version) and `version_count` (the number of versions), on work lists, search, work detail, similar works and recent-play groups, so a list no longer needs one version request per work. `PreparedPlayback` adds the required field `technical_probe` (`not_needed`, `started`, `busy` or `unsupported`): preparing a version that has no MediaInfo yet starts a background probe of the file, and after `started` a later read of the version shows its audio and subtitle tracks. Preload detection: a User-Agent ending in the purpose product `Streamix-Play` is normal playback and `Streamix-Preload` is a preload; without a purpose product, `Sec-Purpose: prefetch` still marks a preload. A preload stream takes no concurrent-stream slot and is not listed as playing; a progress report from a preload returns 409 `prefetch_not_recorded`; while the administrator has switched preloading off, every preload returns 403 `prefetch_disabled`, so stop preloading and do not retry. Capabilities add `features.media_best_version`, `playback_technical_probe`, `prefetch` (whether preloads are currently allowed), `prefetch_user_agent_purpose`, `prefetch_stream_limit_exempt` and `administration_processing_probe_commands`, with no new limits. The full specification also adds three administration operations (run a probe of one version now, retry a probe job, reset the probe jobs of a source); the player subset is unaffected. Check the matching capability before using a new feature; an RC16 or earlier server does not advertise them. Earlier, the RC16 specifications were additive over RC15: the player subset grows from 113 to 116 operations with disc reading: `GET /playback/sessions/{id}/disc` (`DiscListing`: the files of a folder-disc session, each with `id`, `path` below the disc root, `size` and `content_revision`; at most 10000, with `truncated` true when cut) and `GET|HEAD /playback/sessions/{id}/disc/files/{file_id}` (HTTP Range reads of one disc file, with the same request headers as the video stream). `Version` and `PlaybackSession` add the required field `disc` (a nullable `Disc`: a Blu-ray `BDMV` or DVD `VIDEO_TS` folder has `layout` `folder` with `format` `bluray` or `dvd`; an `.iso` image has `layout` `image` with `format` null); `file_size` is null for a folder disc. Behavior change: default playback never picks a disc version; to play one, prepare the session with its `version_id` and `profile.allow_unverified=true`. An image session reads the raw `.iso` bytes through `stream_path` as usual; a folder-disc session answers `stream_path` with 409 `disc_folder`, so read its files through the disc routes instead. The server never transcodes or decrypts a disc. Capabilities add `features.disc_versions` and `disc_folder_files`, with no new limits. The full specification also updates the administration task descriptions (Dolby Vision backfill defaults and failure codes, back-off after a failed TMDB season read); the player subset is unaffected. Check the matching capability before using a new feature; an RC15 or earlier server does not advertise them. Earlier, the RC15 specifications were additive over RC14: the player subset grows from 108 to 113 operations with `GET /episodes/{id}` (one episode by ID, the same shape as the `/media/{id}/children` items), `GET /persons/{id}` (`PersonDetail`: biography, birthday, deathday and place of birth; read again later while `details_state` is `pending`), `GET /media/{id}/images` (`MediaGallery`: backdrop and poster galleries whose items carry `index`, `url`, `width`, `height` and `language`; indexes may have gaps, so fetch each item's `url`), `GET /media/{id}/videos` (`MediaVideoList`: YouTube and Vimeo trailer and featurette links; the server neither downloads nor proxies the videos) and `GET /media/{id}/extras` (`MediaExtraPage`: local trailers and extras on the server, each a `kind`, a `title` and the same `Version` object the version list returns). The image route `GET /media/{id}/images/{kind}` adds `index` (one gallery image) and the poster accepts `season` (season posters). `Media` adds the required fields `tagline`, `tmdb_status`, `status`, `premiere_date`, `studios`, `collection` and `has_backdrop`; `Episode` adds `runtime_minutes`, `duration_ms`, `still` and `rating`; `Season` adds `has_poster`; `VersionDetail` adds `chapters` (nullable `VersionChapters`), `markers` (`SkipMarkers` for intro, recap, credits and preview derived from chapter titles) and `extra`. Behavior change: local trailers and extras are no longer listed as versions of their work; `GET /media/{id}/extras` lists them instead. Capabilities add `features.episode_by_id`, `media_detail_facts`, `person_details`, `media_image_gallery`, `media_videos`, `season_posters`, `episode_ratings`, `version_chapters` and `media_extras`, with no new limits. An RC14 or earlier server does not advertise the RC15 features. Earlier, the RC14 specifications were additive over RC13: the player subset grows from 107 to 108 operations with `GET /media/ids` (the same filters as `GET /media`, returning only work IDs and `updated_at` in ascending ID order, for finding removed or changed works during incremental sync); `GET /media` and `GET /media/initials` add `updated_since` (only works whose `Media.updated_at` is at or after an RFC 3339 instant with offset). `Version` adds the required fields `hdr_type_source` (where `hdr_type` came from: `probe`, `provider` or `filename`; null exactly when `hdr_type` is null) and `dolby_vision` (a nullable `DolbyVisionFacts`: detection state, profile, level, layer layout, FEL/MEL, `base_layer_compatibility` and more); video tracks in the technical details (`TechnicalTrack`, `CompleteInternalTrack`) add the required field `dolby_vision_layer` (`base` or `enhancement`). To rank versions, use `dolby_vision.profile` and `base_layer_compatibility`: prefer Dolby Vision on devices that support it, and on devices that do not, rank versions whose `base_layer_compatibility` is `none` (for example profile 5) last. The `OwnCredential` descriptions of `last_used_at` and `use_count` now include the rate-limited usage record of RC14. Capabilities add `features.media_lookup_by_external_id`, `media_updated_since` and `media_ids`, plus `limits.media_external_ids_max` and `media_ids_page_size_max`. Check the matching capability before using any of them; an RC13 or older server lacks them. Earlier, the RC13 specifications were additive over RC12: the player subset grows from 79 to 107 operations — folder statistics `GET /folders`, playlists under `/users/me/playlists` (list, create, read, rename or change visibility, delete, and entry list, append, remove, move), favorite persons under `/users/me/favorites/persons`, similar titles `GET /media/{id}/similar`, "because you watched" groups `GET /users/me/recommendations/recent-plays`, `GET /episodes/upcoming` and `GET /episodes/missing`, whole-series or season played state `PUT /users/me/media/{id}/played`, season favorites `/users/me/media/{id}/seasons/{season}/state`, the caller's avatar `/users/me/avatar`, plus POST `.../delete` forms of the new DELETE operations. `Media` adds the required fields `tags` and `has_poster`; `PlaybackSession` adds the required fields `file_size`, `bitrate_bps` and `content_revision`; `GET /media` and `GET /media/initials` add `has_poster`, `tag_ids` and `tag_exclude_ids`; sorting adds `last_added_desc`; facets add `tags`. Capabilities add `features.user_playlists`, `folder_statistics`, `favorite_persons`, `media_has_poster`, `similar_media`, `recent_play_recommendations`, `episode_schedule`, `series_played_state`, `season_state`, `user_avatar`, `media_last_added_sort`, `media_tags` and `administration_media_tags`, plus 13 new limits. Check the matching capability before using any of them; an RC12 or older server lacks them or reports false. Earlier, the RC12 specifications were additive over RC11: the player subset grows from 77 to 79 operations (`GET /persons` person search and `GET /episodes` episode search), capabilities add `features.media_quality_filters`, `features.collection_quality_summary`, `features.person_search` and `features.episode_search` plus `limits.search_candidates_max` and `limits.search_page_size_max`, `GET /media` and `GET /media/initials` add the `official_ratings`, `resolutions`, `dynamic_ranges`, `audio_formats`, `audio_languages` and `subtitle_languages` filters, facets add those six kinds plus years, and collection member resources add `quality_summary`. No typed SDK schema, Rust source or Cargo input changes; the SDK uses no new operation, so the minimum server candidate stays **0.9.0-rc.9**. Players that need search, the new filters or collection quality summaries should connect to an RC12 server and check the matching capability. Since RC11, `GET /media` with `include_total=false` returns `total: null`, so `Page.total` is `Option<i64>`; the SDK's own requests never send that parameter. The SDK still requires `features.playback_ticket_header=true` and `features.credentials_in_urls=false`. The server also exposes the additive aliases `features.stream_ticket_header=true` and `features.stream_query_ticket=false`. Protocol version `1.0` alone is insufficient; there is no credential-URL fallback.

[Connection guidance](docs/connecting.md), [discovery guidance](docs/discovery.md) and [client request headers](docs/client-request-headers.md) define trusted origins, local-HTTP opt-in, ports, metadata, per-install UUIDs, purpose and tracing. UDP client networking is not implemented here; deployment and real-LAN acceptance remain separate.

The Rust candidate models login, browsing, versions, prepared playback sessions, ticket renewal, a bounded byte range, progress and explicit session termination. Video requests use `X-SXAPI-Stream-Ticket`; subtitles additionally retain the original login Bearer. Streamix Server currently serves the original file without transcoding. Players must declare their actual supported formats.

TypeScript, Swift and Kotlin SDKs are unimplemented future work. No packages for those languages are advertised or published.

This public repository contains client contracts and integration source only. Specifications are synchronized from the server-generated full and client specifications and must not be edited here.
