# Version and compatibility

Kit version: **0.1.0-rc.2**. Build: **20261112.011**. Protocol: **SXAPI major 1**, base `/sxapi/v1`.

The minimum server source requirement is candidate **0.9.0-rc.9**. The specifications are bound to upstream commit `454e2e791bf838dd5caf13f75ad8e579d7608819` (intended server version 0.9.0-rc.15) in [SOURCE.json](../spec/SOURCE.json). The full/client SHA256 values identify the exact synchronized bytes. No upstream release reference is supplied because this candidate is unpublished; compatibility remains NOT_VALIDATED. The bound commit itself passed the server API documentation checks. Source binding is not SDK CI or integration acceptance. This candidate depends on the new header-only video and subtitle contract, not the old URL-ticket transport. Do not advertise compatibility with RC8 or a historical server from a version string alone.

The RC15 specifications are additive over RC14: the player subset grows from 108 to 113 operations with `GET /episodes/{id}` (one episode by ID, the same shape as the `/media/{id}/children` items), `GET /persons/{id}` (`PersonDetail`: biography, birthday, deathday and place of birth; read again later while `details_state` is `pending`), `GET /media/{id}/images` (`MediaGallery`: backdrop and poster galleries whose items carry `index`, `url`, `width`, `height` and `language`; indexes may have gaps, so fetch each item's `url`), `GET /media/{id}/videos` (`MediaVideoList`: YouTube and Vimeo trailer and featurette links; the server neither downloads nor proxies the videos) and `GET /media/{id}/extras` (`MediaExtraPage`: local trailers and extras on the server, each a `kind`, a `title` and the same `Version` object the version list returns). The image route `GET /media/{id}/images/{kind}` adds `index` (one gallery image) and the poster accepts `season` (season posters). `Media` adds the required fields `tagline`, `tmdb_status`, `status`, `premiere_date`, `studios`, `collection` and `has_backdrop`; `Episode` adds `runtime_minutes`, `duration_ms`, `still` and `rating`; `Season` adds `has_poster`; `VersionDetail` adds `chapters` (nullable `VersionChapters`), `markers` (`SkipMarkers` for intro, recap, credits and preview derived from chapter titles) and `extra`. Behavior change: local trailers and extras are no longer listed as versions of their work; `GET /media/{id}/extras` lists them instead. Capabilities add `features.episode_by_id`, `media_detail_facts`, `person_details`, `media_image_gallery`, `media_videos`, `season_posters`, `episode_ratings`, `version_chapters` and `media_extras`, with no new limits. Check the matching capability before using a new feature; an RC14 or earlier server does not advertise them.

The RC14 specifications are additive over RC13: the player subset grows from 107 to 108 operations with `GET /media/ids` (the same filters as `GET /media`, returning only work IDs and `updated_at` in ascending ID order, for finding removed or changed works during incremental sync); `GET /media` and `GET /media/initials` add `updated_since` (only works whose `Media.updated_at` is at or after an RFC 3339 instant with offset). `Version` adds the required fields `hdr_type_source` (where `hdr_type` came from: `probe`, `provider` or `filename`; null exactly when `hdr_type` is null) and `dolby_vision` (a nullable `DolbyVisionFacts`: detection state, profile, level, layer layout, FEL/MEL, `base_layer_compatibility` and more); video tracks in the technical details (`TechnicalTrack`, `CompleteInternalTrack`) add the required field `dolby_vision_layer` (`base` or `enhancement`). To rank versions, use `dolby_vision.profile` and `base_layer_compatibility`: prefer Dolby Vision on devices that support it, and on devices that do not, rank versions whose `base_layer_compatibility` is `none` (for example profile 5) last. The `OwnCredential` descriptions of `last_used_at` and `use_count` now include the rate-limited usage record of RC14. Capabilities add `features.media_lookup_by_external_id`, `media_updated_since` and `media_ids`, plus `limits.media_external_ids_max` and `media_ids_page_size_max`. No typed SDK schema, Rust source or Cargo input changes; the typed `Version` keeps reading its existing fields and treats the new ones as unknown, so the minimum server candidate stays **0.9.0-rc.9**. Players that need these features should connect to an RC14 server and check the matching capability.

The RC13 specifications are additive over RC12: the player subset grows from 79 to 107 operations — folder statistics `GET /folders`, playlists under `/users/me/playlists` (list, create, read, rename or change visibility, delete, and entry list, append, remove, move), favorite persons under `/users/me/favorites/persons`, similar titles `GET /media/{id}/similar`, "because you watched" groups `GET /users/me/recommendations/recent-plays`, `GET /episodes/upcoming` and `GET /episodes/missing`, whole-series or season played state `PUT /users/me/media/{id}/played`, season favorites `/users/me/media/{id}/seasons/{season}/state`, the caller's avatar `/users/me/avatar`, plus POST `.../delete` forms of the new DELETE operations. `Media` adds the required fields `tags` and `has_poster`; `PlaybackSession` adds the required fields `file_size`, `bitrate_bps` and `content_revision`; `GET /media` and `GET /media/initials` add `has_poster`, `tag_ids` and `tag_exclude_ids`; sorting adds `last_added_desc`; facets add `tags`. Capabilities add `features.user_playlists`, `folder_statistics`, `favorite_persons`, `media_has_poster`, `similar_media`, `recent_play_recommendations`, `episode_schedule`, `series_played_state`, `season_state`, `user_avatar`, `media_last_added_sort`, `media_tags` and `administration_media_tags`, plus 13 new limits. No typed SDK schema, Rust source or Cargo input changes; the typed `Media` and `PlaybackSession` keep reading their existing fields and treat the new ones as unknown, so the minimum server candidate stays **0.9.0-rc.9**. Players that need these features should connect to an RC13 server and check the matching capability.

The RC12 specifications are additive over RC11: the player subset grows from 77 to 79 operations (`GET /persons` person search and `GET /episodes` episode search), capabilities add `features.media_quality_filters`, `features.collection_quality_summary`, `features.person_search` and `features.episode_search` plus `limits.search_candidates_max` and `limits.search_page_size_max`, `GET /media` and `GET /media/initials` add the `official_ratings`, `resolutions`, `dynamic_ranges`, `audio_formats`, `audio_languages` and `subtitle_languages` filters, facets add those six kinds plus years, and collection member resources add `quality_summary`. No typed SDK schema, Rust source or Cargo input changes; the SDK uses no new operation, so the minimum server candidate stays **0.9.0-rc.9**. Players that need search, the new filters or collection quality summaries should connect to an RC12 server and check the matching capability. Since RC11, `GET /media` with `include_total=false` returns `total: null`, so `Page.total` is `Option<i64>`; the SDK's own requests never send that parameter.

The RC11 specifications are additive over RC10: the player subset grows from 70 to 77 operations (`GET /users/me/resume`, `GET /users/me/next-up`, `GET /media/initials`, plus POST forms of logout, session end, credential revocation and stream termination), capabilities add `features.list_user_state`, `features.watch_queues`, `features.media_initials` and `features.subtitle_match`, lists and details add `user_state`, `external_ids.tvdb` and `has_logo`, subtitles add `match` and `other_version`, `/media` adds external-ID, initial-letter, multi-genre, in-progress, sort and `include_total` options, and JSON reads support ETag/304. The only typed SDK change: `GET /media` with `include_total=false` returns `total: null`, so `Page.total` becomes `Option<i64>`; the SDK's own requests never send that parameter and still receive a number. The SDK uses no other new operation, so the minimum server candidate stays **0.9.0-rc.9**. Players that need the new lists, filters or user state should connect to an RC11 server and check the matching capability.

Before usage require runtime capabilities `playback_ticket_header=true`, `credentials_in_urls=false` and the needed individual features. The server also declares the additive aliases `stream_ticket_header=true` and `stream_query_ticket=false`; these do not enable a URL transport or change the SDK checks. Missing capability keys are unsupported. No lenient legacy fallback is provided. A deployment can disable features even when the protocol/schema is present.

Kit uses its own SemVer. Pre-release server integrations use a pre-release Kit until formally accepted; a final server release does not automatically finalize this Kit. Breaking SXAPI changes require a new protocol major path and a corresponding Kit major. Compatible additive fields may be retained as unknown fields by typed response models.

`sync_spec.py` records the full upstream commit, release, minimum server version, synchronized timestamp and SHA256 of the exact full and player-subset bytes. Both must come from the same reviewed generation. CI rejects local edits, source drift and a subset that differs from the server generation.

Delivery stages remain distinct: source, static review, server CI/mock tests, real test-server flow, Draft PR review, merge, release, SDK distribution and real-player decoding. Each claim needs its own evidence; not-run is not passing.
